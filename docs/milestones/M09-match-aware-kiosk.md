# Milestone 9 — Match-aware kiosk view

> A logged-in player should see the kiosk for the container they're playing in (and only that one), automatically. The existing per-container kiosk at [sveltekit/src/routes/containers/[name]/+page.svelte](../sveltekit/src/routes/containers/[name]/+page.svelte) is admin-gated and assumes you know the container name. Replace that mental model with "log in → see your match", driven by gamertag-to-machine-name detection inside the running scraper data.

## 9a. Gamertag → machine-name detection

Each scraper runner already exposes the local Xbox machine name and the network player roster (machines + gamertags) via the M5 `instanceCache`. Extend the runner to publish a `(container, machines[], gamertags[])` membership view — likely a new field on the `host:all` summary aggregator in [internal/scraper/manager/aggregator.go](../internal/scraper/manager/aggregator.go). The same view feeds M10's overlay routing.

## 9b. Per-user "my match" page

New route at `/play/` (or `/my-match/`). Subscribes to `host:all`, finds the container whose roster contains any of the logged-in user's gamertags (from M7c), then renders the existing kiosk iframe + controller UI for that container. Renders blank/idle state otherwise. Auto-refreshes if the user's gamertag appears on a different container later.

## 9c. WS auth narrowing

Today `host:<name>` requires admin. Extend the room guard so a non-admin user is permitted to join `host:<name>` if they have a gamertag in that container's roster. New room-level guard in [internal/websocket/rooms/host.go](../internal/websocket/rooms/host.go) or a new sibling guard, consuming the new role helpers from M8c so admins always get in regardless of roster membership. Keep `host:all` admin-only (it's a cross-instance summary).

Smoke test: 4-container match, 4 logged-in users with one gamertag each, each gamertag mapped to one container's local Xbox machine. Each user opens `/play/` → sees only their container's kiosk. Admin opens `/play/` while not playing → blank state, but admin can still hit `/containers/<name>/` directly. User logs in but isn't in any active match → blank state.

- 2026-06-16: First increment — 9a + 9b + 9c implemented end-to-end (code-complete; pending the live 4-container smoke test, which needs podman + xemu and can't run in CI). Design notes + deviations from the original sketch:
  - **9a — membership view.** Added `scraperiface.ContainerMembership{Container, Identities}` + `Manager.Membership()` ([internal/scraper/manager/membership.go](../internal/scraper/manager/membership.go)) rather than bolting a field onto the `host:all` aggregator. `Identities` is the deduped, sanitized union of the local Xbox console name + system-link machine names + in-game player roster names, so a user's gamertag matches whether they registered their console name or their in-game name. Pure match helpers (`MatchContainer`, `ContainerHasGamertag`, `SanitizeIdentity`) live in [internal/guards/interfaces/scraper/membership.go](../internal/guards/interfaces/scraper/membership.go) so the resolver, WS guard, and proxy share one tested code path (import-cycle-free). Unit-tested in both packages.
  - **9b — match resolution is server-side, not via `host:all`.** The original sketch had `/play/` subscribe to `host:all` and match client-side. But 9c keeps `host:summary`/`host:all` admin-only, so a non-admin can't read the cross-instance feed. Resolution therefore happens server-side: new `GET /api/me/match` ([internal/pocketbase/routes/me_match.go](../internal/pocketbase/routes/me_match.go), RequireAuth) resolves the caller's non-blocked sanitized gamertags (shared helper [internal/gamertags/gamertags.go](../internal/gamertags/gamertags.go)) against `Manager.Membership()` and returns `{container}` or `{container: null}`. The `/play/` page ([sveltekit/src/routes/play/](../sveltekit/src/routes/play/)) polls it (initial load + window `focus` + 5s visible-tab interval — matches the M23b poll-on-focus pattern) and renders a lean `PlayKiosk` (reuses `KioskFrame` + `XboxController` + `VNCKeyboard`, minus the admin-only container-detail fetch + start/stop controls that made `ControlsTab` admin-bound). Note the M09 doc's `containers/[name]/+page.svelte` reference is pre-M06 — the kiosk moved to `/admin/pod/[name]/` in the M06 pod restructure.
  - **9c — WS narrowing + proxy narrowing.** Room guards (`RoomType.Guards`) don't receive the room name, so the per-room narrowing lives in the `join_room` handler ([internal/websocket/handlers/join_room.go](../internal/websocket/handlers/join_room.go)): `host:summary`/`host:all` stay admin-only; `host:<instance>[:class]` additionally admits a roster member of that specific instance; admins bypass via `roles.IsAdminAuth` (M08). **Also narrowed the kiosk HTTP proxy + VNC relay** ([internal/pocketbase/routes/containers/auth.go](../internal/pocketbase/routes/containers/auth.go) `authorizeKioskAccess`) the same way — without this the `/play/` kiosk iframe + controller would 403 for the very players the milestone targets. Access is re-checked per request (every sub-resource / websockify upgrade), so it lapses the moment a player leaves the match. Fails closed on any lookup error.
  - **Deferred:** the live 4-container smoke test (manual, podman-gated — the only M09 verification step CI can't cover). Per-request `Membership()` snapshotting on non-admin kiosk sub-resources is acceptable at current scale; revisit with a short TTL cache if container counts grow. Reusing the membership view for M10 overlay routing remains M10's job.
