# Milestone 19 — Robustness + offset validation

> Split from the original M8 (Robustness + Discord + auth). The Discord pieces (commands, channel posting) are subsumed by M17; the auth-wrapping work is mostly addressed by M6a + M7c + M8 + M9c; multi-user UX is covered by M15/M16. What remains is the "make silent bad data become loud errors" work, plus general operational hardening.

- **19a. Runtime offset sanity checks.** Apply to both Halo: CE and Halo 2 (whenever it lands). Base-HVA range checks, magic-value probes, plausibility bounds on read values. Loud error (log + WS notification + admin debug page badge) on sanity-check fail.
- **19b. Field-level validation.** Use the M6c debug-page audit's "looks plausible / clearly broken" annotations as input — promote validated fields out of `unverified` status, file remaining `unverified` fields as offset-investigation tasks.
- **19c. PB queue + scraper resilience.** Polish M13d's queue logic; add metrics; ensure scraper restarts cleanly after PB outages.

Smoke test: deliberately corrupt an offset in the Halo: CE table → loud error fires within one read; recover by reverting; confirm no silent bad-data writes to PB.

- 2026-05-19: **closes the 2026-05-18 offset hypothesis**. Diagnostic logging added to both readers (`gate=` + raw value counters), then offsets re-derived via two memory-probe agent passes against a live `debug-host` container running Halo CE Xbox. Findings:
  - `readObjectTypes`: `RefAddrObjectTypeDefRangeLo` (0x1FC0D0) and `RefAddrObjectTypeDefRangeHi` (0x1FCBA4) are **literal address bounds**, not pointers to dereference. Halocaster.py:344 misled the Go port. Array of 11 type-def pointers lives at `RefAddrObjectTypeDefArray = 0x1FCB78`; count = (Hi - Array) / 4 = 11. Each pointer points to a struct in low-GVA space (engine .data, ~0x001FCxxx range) and must be translated via QMP per-pointer (`RefreshLowHVA`), not via `HighGVA` arithmetic. Per-type field at +0x00 is a self-pointer/vtable on Xbox (NOT a string pointer as halocaster.py:736 claimed) — names hardcoded from the fixed 11-type order. Datum size at +0x08 is correct.
  - `readPowerSpawnScenarios`: tag reference at scenario_item+0x5C is a **u32 tag handle** (high16=salt, low16=index, 0xFFFFFFFF=empty), not s32 tag index — halocaster.py:648 was wrong. itmc respawn time is at `tag_data+0x0C` directly as s16 seconds (no PC-style `+0x14 → ptr → +0x0C` indirection). Per-placement override at `scenario_item+0x0E` (previously misnamed `OffScenItemUnknownAttr`) takes precedence when non-zero. `TicksPerSecond=30` added; both reads multiplied by it so wire stays in tick units.
  - Also added `power_item_spawns[].gametype_mask` from `scenario_item+0x04` so consumers can distinguish per-gametype variants of the same physical placement (CTF rocket-spawn-30s vs Slayer rocket-spawn-120s at identical coordinates).
  - Verification (chillout seq=3 tick=2595955): `object_types` has all 11 entries with correct names + datum sizes; `power_item_spawns` has 16 entries (full chillout item array including grenade boxes); intervals match canonical Halo CE values (camo/overshield 60s default → 1800 ticks, rocket 120s → 3600, sniper/grenades 30s overrides → 900). downrush also fully populated (34 entries).
